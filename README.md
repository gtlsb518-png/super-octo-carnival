# 바이낸스 선물 자동매매 봇

UT Bot + EMA 크로스 신호 기반 바이낸스 USDT-M 선물 자동매매 프로그램 (tkinter GUI).

## 실행 방법

```bash
python 9_main.py
```

필요한 라이브러리(pandas, numpy, requests, openpyxl)는 실행 시 자동 설치됩니다.
tkinter가 없는 리눅스에서는 `sudo apt-get install python3-tk`로 설치하세요.

## 설정

`1_config.py`에서 수정:

- `API_KEY` / `API_SECRET`: 바이낸스 API 키 (현재 테스트넷 키)
- `TESTNET`: `True`=테스트넷(데모), `False`=메인넷(실거래)

첫 실행 후에는 `settings.json`이 생성되어 그 값이 우선 적용됩니다.

⚠️ 메인넷 키를 사용할 경우 절대 저장소에 커밋하지 마세요.

## 매매 로직 요약

- **진입**: UT Bot 상태 + EMA(34/55) 크로스 AND 조건, 코인당 LONG/SHORT 봇 각 1개 (기본 1시간봉)
- **UT Bot**: Key Value 10, ATR Period 5 (시뮬레이션상 ATR 2와 수익은 동등하나 거래·수수료·낙폭이 적음)
- **레버리지**: 5배 격리 (`1_config.py` 의 `LEVERAGE`)
- **신호 기준** (`SIGNAL_MODE`): 기본 `"ut_close"` — **UT 는 봉 마감 기준, EMA34/55 는 실시간**.
  봉 중간에 UT 신호가 바뀌어도(리페인팅) 무시하고, EMA 크로스는 바로 반영.
  `"live"` = 둘 다 진행 중 봉(예전 방식, 리페인팅 추적 로그 붙음) / `"confirmed"` = 둘 다 봉 마감
- **익절**: ADX(기간 10, 1시간봉) 기반 동적 TP — 추세장(ADX≥21) 1.5% / 횡보장 1.2%
- **스위칭 시점** (`SWITCH_MODE`): 기본 `"close"` — 반대 신호가 **봉 마감으로 확정됐을 때만** 스위칭 (UT·EMA 둘 다 마감 기준,
  봉이 끝나면 다음 봉 시작에 스위칭). 봉 중간에 EMA 가 잠깐 크로스했다가 마감 전에 돌아오는 경우엔 스위칭 안 함.
  `"live"` = 신호 기준대로 봉 중간에도 바로 스위칭 (예전 방식). 테스트넷 1주 운영 결과 봉 중간 스위칭이 손해라 기본을 바꿈
- **익절 후 재진입** (`REENTRY`): 기본 `"immediate"` — 익절 후 신호가 그대로면 **바로 재진입** (익절이 계속 이어짐).
  `"next_bar"` = 익절한 봉에서는 쉬고 다음 봉에서 신호 확인 후 진입 (체결 시각 기준, 재시작·꺼진 사이 익절도 이어서 대기)
- **⏹️ 전체 롱숏 종료**: **이 프로그램의 코인만** 정지·청산합니다. 같은 계정에서 도는 다른 프로그램의 포지션은 건드리지 않습니다
- **통신 장애**: 포지션 조회가 실패하면 1.5 → 3 → 6 → 12 → 최대 15초 간격으로 다시 시도 (장애 때 요청 폭주 → IP 차단 방지).
  그동안 익절·스위칭 판단은 마지막으로 받은 포지션(30초 이내)으로 하고, 청산 주문은 reduceOnly 라 안전
- **손절/스위칭**: 고정 손절 없음 — 보유 중 역신호(UT+EMA) 발생 시 청산 후 즉시 반대 방향 진입 (AUTO 스위칭이 유일한 손절 수단)
- 차트 데이터는 항상 메인넷 시세, 주문은 테스트넷/메인넷 선택
- 거래 기록은 `trade_history.xlsx`, 통계는 `bot_stats.json`에 저장

### 📊 화면 통계 = 바이낸스 기록 (컴퓨터를 바꿔도 같은 숫자)

화면의 순수익·수수료·펀딩·거래 횟수·승률은 시작 시각(`bot_stats.json` 에 저장, 또는 `1_config.py` 의 `STATS_START_DATE`) 이후
**바이낸스 체결 기록(`userTrades`)과 펀딩 기록(`income`)으로 다시 계산**한 값입니다.

- 예전엔 이 컴퓨터의 `bot_stats.json` 에만 더해 나가서 다른 컴퓨터에서 켜면 0부터 시작했고,
  진입 수수료가 두 번 빠지는 버그가 있었습니다 → 둘 다 해결
- 체결을 시간순으로 따라가며 수량이 0이 되는 지점까지를 거래 1건으로 셉니다
  (부분 체결 합침, 청산+반대진입 한 번에 된 주문은 수수료를 수량 비율로 나눔)
- 아직 열려 있는 포지션의 진입 수수료는 수수료 합계와 순수익에 이미 반영
- BNB로 낸 수수료는 USDT로 환산. 펀딩비는 코인별로 따로 표시
- 켤 때 한 번 전부 계산 → 이후 진입·청산한 코인은 바로, 전체는 2분마다, 펀딩은 10분마다
- 조회가 실패하면 기존 숫자를 그대로 두고 다음에 다시 시도
- 초기화: `bot_stats.json` 을 지우고 켜면 지금부터 새로 셈. 다른 컴퓨터에서 이어 보려면 그 파일을 복사
- 바이낸스는 체결 기록을 최근 6개월까지만 주므로 그보다 오래된 날짜는 6개월 전으로 맞춰집니다

### 📏 주문 수량 소수점

수량 소수점은 코드에 적어두지 않고 **바이낸스 거래소 정보(`exchangeInfo`)의 stepSize·minQty·tickSize를 그대로** 씁니다.
켤 때 코인마다 단위와 실제 주문 수량을 콘솔에 표시하고, 진입이 안 되는 코인은 ❌ 로 알려줍니다.

```
📏 주문 수량 소수점 점검 (진입금 × 레버리지 기준, 프로그램 #2)
   BCH/USDT   단위 0.001  최소 0.001  호가 0.01     → 0.3개 = 150.0 USDT ✅
   ATOM/USDT  단위 0.01   최소 0.01   호가 0.001    → 33.33개 = 150.0 USDT ✅
```

### 🔌 웹소켓 (`WEBSOCKET_MODE`)

- `off` = 조회(REST)만 / `shadow` = 웹소켓은 비교만, 매매는 조회 / `on`(기본) = 차트(kline 스트림, 메인넷 `/market`)와
  계좌 알림(user data stream, `/private`)을 웹소켓으로 받음
- `on` 에서 봇 코드는 그대로이고 `get_klines`·포지션 캐시만 웹소켓 값을 씀 → 프로그램당 분당 약 600 → 약 100
- 끊김: 자동 재접속 + 조회로 대체(IP 사용량 따라 자동 감속), 재접속 시 빠진 봉 채움, 봉 멈춘 코인 감지, 5분마다 조회와 대조, listenKey 30분 연장·만료 시 재발급
- 모든 모드에서 응답 헤더 `X-MBX-USED-WEIGHT-1M`(IP 전체 사용량)을 보고 많으면 조회 간격을 자동으로 늘림
- 청산 주문은 모두 `reduceOnly` (거래소 TP 와 동시에 나가도 반대 포지션이 안 열림)

### 📒 엑셀 거래 기록 (`trade_history.xlsx`)

| 시트 | 내용 | 값의 출처 |
|---|---|---|
| **바이낸스 거래내역** (맨 앞) | 바이낸스 선물 '거래 내역'과 같은 칸: 시간·심볼·방향·가격·수량·체결금액·수수료·수수료 자산·역할·실현 손익·주문번호·체결번호 | 바이낸스 체결 원본(`/fapi/v1/userTrades`) 그대로 |
| 코인별 시트 (BTC, ETH …) | 거래 1건당 1줄 요약: ROI·수익/손실·진입/청산 수수료·순수익·거래유형 | 같은 체결 원본에서 그 거래의 체결들을 모아 계산 |

- '바이낸스 거래내역'은 5분마다, 그리고 청산 직후 바로 갱신됩니다. 최신 체결이 맨 위(바이낸스 화면과 같은 순서)
- 체결번호로 이어 적어서 중복 없이 쌓이고, 프로그램을 다시 켜도 이어집니다. 처음 켤 때는 최근 7일치를 가져옵니다
- 부분 체결(한 주문이 여러 조각으로 체결)도 조각마다 한 줄씩, 바이낸스와 똑같이 기록됩니다
- 수수료를 BNB로 냈으면 거래내역 시트엔 BNB 그대로, 코인별 요약엔 USDT로 환산해서 적습니다
- 엑셀 파일을 열어두면 그동안은 저장을 건너뛰고 다음 주기에 이어서 적습니다
- 펀딩비는 바이낸스에서도 '거래 내역'이 아닌 '거래 기록(자산 내역)'에 따로 나오므로 이 시트에는 없습니다

### 🔄 시작 시 기존 포지션은 청산하지 않음

시작 버튼을 눌러도 바이낸스에 열려 있는 포지션을 닫지 않습니다. 그대로 이어받습니다.

| 상황 | 동작 |
|---|---|
| 인터넷만 끊겼다 복구 | 봇이 알아서 이어서 돎 (버튼 누를 필요 없음) |
| 프로그램 재시작 | 자동 재연결로 포지션 이어받음 |
| **시작 버튼 (포지션 있음)** | **청산 없이 이어받음** — 진입가·ROI·TP 복원 |
| **시작 버튼 (이미 실행 중)** | **아무것도 안 함** — ROI·진입가 초기화 안 됨 |
| 시작 버튼 (API 응답 없음) | 포지션에 손대지 않고 시작 |
| 시작 버튼 (포지션 없음) | 잔여 주문 정리 후 깨끗하게 시작 |

이어받을 때 바이낸스 실제 값으로 진입가·ROI를 복원하고, TP 기준이 없으면
현재 ADX로 다시 정한 뒤 거래소 TP 주문을 재등록합니다.

### 🛑 수동청산 · 강제청산 시 자동 정지

포지션이 봇을 거치지 않고 사라지면 원인을 판별해서 다르게 처리합니다.

| 원인 | 판별 기준 | 봇 동작 |
|---|---|---|
| 봇이 건 TP 주문 체결 | 주문 `type`이 `TAKE_PROFIT_MARKET` | ✅ 계속 — 정상 익절 |
| 사람이 바이낸스에서 수동 청산 | 그 외 체결 주문 | 🛑 **이 코인 정지** |
| 바이낸스 강제청산 / ADL | `clientOrderId`가 `autoclose-` / `adl_autoclose`로 시작 | 🛑 **이 코인 정지** |

주문 조회가 실패하면 손익 부호로 보수적으로 추정합니다.
봇 TP는 +1.5%에서만 체결되므로, **손실이면 TP일 수 없다** → 정지합니다.

**정지 범위**
- 해당 코인의 `long_active` / `short_active`만 끕니다
- 스레드는 살아 있어 **프로그램도, 다른 코인도 그대로** 돌아갑니다
- 남아있는 예약 주문(TP 등)은 정리합니다

```
🛑 SUI/USDT 봇 정지 — 수동청산 감지
   이 코인만 멈췄습니다. 다른 코인·프로그램은 그대로 돌아갑니다.
   ▶️ 다시 매매하려면 시작(또는 강제시작) 버튼을 누르세요.
```

**재개**: 시작 / 강제시작 버튼을 누르면 정지 상태가 풀리고 다시 진입합니다.
프로그램을 껐다 켜도(자동 재연결) **정지한 코인은 멈춘 채로** 둡니다 (`bot_running.json` 에 기록).
콘솔에 `🛑 XRP/USDT 정지 상태 유지 (수동청산) — 다시 매매하려면 시작 버튼` 이 나옵니다.
'전체 롱숏 시작'을 누르거나 그 코인의 시작 버튼을 누르면 풀립니다.

### 💸 펀딩비 로그

선물은 포지션을 들고만 있어도 8시간마다 펀딩비를 냅니다. 봇이 이를 코인별로 알려줍니다.

**진입 시 — 지금 비율이 얼마고 다음 정산이 언제인지**
```
💸 펀딩비율 +0.0100% → 1회당 낼 돈 $0.015 (다음 정산 24분 뒤)
```
비율이 양수면 LONG이 내고 SHORT이 받습니다(음수면 반대). 방향에 맞춰 '낼 돈/받을 돈'으로 표시합니다.
비율이 0.05% 이상이면 경고가 추가로 붙습니다.

**보유 중 — 새로 정산될 때마다 (8시간에 한 번)**
```
💸 TRX/USDT 펀딩비 정산 — 이번에 $0.012 냄 (SHORT 보유 중)
   프로그램 켠 뒤 이 코인 합계: $0.011 받음 (정산 4회)
```
- **이번에** = 방금 정산된 한 번의 금액 (냄 / 받음)
- **합계** = 프로그램을 켠 뒤 이 코인에서 정산된 펀딩비를 모두 더한 값
- 실제 보유 방향(LONG/SHORT) 로그에 찍힙니다

추정치가 아니라 바이낸스 계좌 기록(`/fapi/v1/income`)에서 읽은 **실제 금액**입니다.
펀딩은 정각에만 정산되므로 **정각이 지나고 1분 반~5분 반 뒤에 코인당 한 번만** 조회하고
(코인마다 시각을 조금씩 나눠 한꺼번에 몰리지 않게), 새 정산이 있을 때만 기록합니다.
청산할 때 '들고 있는 동안의 펀딩비'도 보유 중 정각을 지난 경우에만 조회합니다 (안 지났으면 0).
조회 1번이 가중치 30이라 익절이 잦을수록 아끼는 양이 큽니다.

⚠️ 테스트넷은 펀딩비율이 실제 시장과 다릅니다. 비율 조회는 항상 메인넷 기준이고,
실제 납부액은 주문 서버(테스트넷/메인넷) 기록을 따릅니다.

### 🔍 리페인팅 추적 로그 (즉시 진입 모드)

진행 중인 봉 신호로 들어가면 그 신호는 봉이 닫히기 전까지 사라질 수 있습니다(리페인팅).
어떤 거래가 그런 진입이었는지 로그로 남습니다.

**진입 시점**
```
✅ LONG 진입! $60,123.45 | 0.002개 | 1h | 3x
   ⚡ #7번 거래 — 진행 중인 봉(03/14 15:00) 신호로 진입
      → 아직 리페인팅 가능. 이 봉이 닫히면 확정 여부를 알려드립니다.
```

**기준봉이 닫힌 뒤 (자동으로 따라붙음)**
```
🔍 #7번 거래 — 기준봉(03/14 15:00) 마감 → ✅ 신호 확정 (리페인팅 없었음)
      ↳ 이 거래는 아직 보유 중입니다
```
또는
```
🔍 #7번 거래 — 기준봉(03/14 15:00) 마감 → ⚠️ 리페인팅 발생! 확정봉 기준으론 없던 신호였습니다
      ↳ 이 거래는 기준봉이 닫히기 전에 이미 청산됐습니다 (리페인팅 피함)
```

거래번호(#N)는 코인별로 1번부터 매겨지며 LONG/SHORT 봇이 함께 씁니다.
'봉 확정 후' 모드에서는 리페인팅이 원천적으로 없으므로 이 로그가 나오지 않습니다.

## 백테스터 (`backtest.py`)

```bash
python backtest.py                # GUI
python backtest.py --symbols BTCUSDT --funding 0.03 --capital 250
```

봇과 같은 지표·로직을 쓰되, 실제 계좌에서만 생기는 두 가지 비용/제약을 반영합니다.

### 💸 펀딩비

선물은 포지션을 들고만 있어도 8시간마다 펀딩비를 냅니다. 1시간봉은 평균 15~26시간 보유하므로
거래당 2~3번씩 내게 되고, **거래 수수료보다 커질 수 있습니다.**

| 펀딩비(8h당) | 상황 | 연 수익 영향 (변동성 80% 코인, 1년) |
|---|---|---|
| 0% | 미반영 | +80.7 (부풀려진 값) |
| 0.01% | 평온한 장 | +65.9 (펀딩 -14.6) |
| 0.03% | 보통 | +36.5 (펀딩 -43.9) |
| 0.05% | 과열장·알트 | +7.1 (펀딩 -73.2 — 수수료 51.5보다 큼) |

기본값 0.01%. 추세추종 봇은 대개 '쏠린 쪽'에 서 있어 롱·숏 모두 내는 쪽이 되므로
양방향 비용으로 계산합니다(보수적).

### 🏦 계좌 잔고 한도

기본 백테스트는 **돈이 안 떨어진다고 가정**해서, 실제로는 청산당했을 구간도 계속 매매합니다.
`capital`(코인당 잔고)을 넣으면 현실대로 동작합니다.

- 잔고 < 진입금 → 진입 못 함 (놓친 구간 집계)
- 잔고 ≤ 0 → **파산 처리 후 그 시점에 매매 중단**
- `필요잔고` 컬럼: 중간에 안 끊기려면 필요한 최소 계좌 규모 (= 진입금 + 누적손익 최저점)

여러 코인을 동시에 돌리면 코인간 상관이 높아(상위10 기준 ≈0.7) 낙폭이 **코인 1개의 4배 이상**으로
겹칩니다. `필요잔고`를 코인 수만큼 단순 합산하지 말고, 넉넉하게 잡으세요.
