# 바이낸스 선물 자동매매 봇

UT Bot + EMA 크로스 신호 기반 바이낸스 USDT-M 선물 자동매매 프로그램 (tkinter GUI).

## 실행 방법

```bash
python 9_main.py
```

필요한 라이브러리(pandas, numpy, requests, openpyxl)는 실행 시 자동 설치됩니다.
tkinter가 없는 리눅스에서는 `sudo apt-get install python3-tk`로 설치하세요.

## 설정

`1_config.py`에서 수정:

- `API_KEY` / `API_SECRET`: 바이낸스 API 키 (현재 테스트넷 키)
- `TESTNET`: `True`=테스트넷(데모), `False`=메인넷(실거래)

첫 실행 후에는 `settings.json`이 생성되어 그 값이 우선 적용됩니다.

⚠️ 메인넷 키를 사용할 경우 절대 저장소에 커밋하지 마세요.

## 매매 로직 요약

- **진입**: UT Bot 상태 + EMA(34/55) 크로스 AND 조건, 코인당 LONG/SHORT 봇 각 1개 (기본 1시간봉)
- **익절**: ADX(기간 10, 1시간봉) 기반 동적 TP — 추세장(ADX≥21) 1.5% / 횡보장 1.2%
- **손절/스위칭**: 고정 손절 없음 — 보유 중 역신호(UT+EMA) 발생 시 청산 후 즉시 반대 방향 진입 (AUTO 스위칭이 유일한 손절 수단)
- 차트 데이터는 항상 메인넷 시세, 주문은 테스트넷/메인넷 선택
- 거래 기록은 `trade_history.xlsx`(코인별 시트), 통계는 `bot_stats.json`에 저장

## 백테스터 (`backtest.py`)

```bash
python backtest.py                # GUI
python backtest.py --symbols BTCUSDT --funding 0.03 --capital 250
```

봇과 같은 지표·로직을 쓰되, 실제 계좌에서만 생기는 두 가지 비용/제약을 반영합니다.

### 💸 펀딩비

선물은 포지션을 들고만 있어도 8시간마다 펀딩비를 냅니다. 1시간봉은 평균 15~26시간 보유하므로
거래당 2~3번씩 내게 되고, **거래 수수료보다 커질 수 있습니다.**

| 펀딩비(8h당) | 상황 | 연 수익 영향 (변동성 80% 코인, 1년) |
|---|---|---|
| 0% | 미반영 | +80.7 (부풀려진 값) |
| 0.01% | 평온한 장 | +65.9 (펀딩 -14.6) |
| 0.03% | 보통 | +36.5 (펀딩 -43.9) |
| 0.05% | 과열장·알트 | +7.1 (펀딩 -73.2 — 수수료 51.5보다 큼) |

기본값 0.01%. 추세추종 봇은 대개 '쏠린 쪽'에 서 있어 롱·숏 모두 내는 쪽이 되므로
양방향 비용으로 계산합니다(보수적).

### 🏦 계좌 잔고 한도

기본 백테스트는 **돈이 안 떨어진다고 가정**해서, 실제로는 청산당했을 구간도 계속 매매합니다.
`capital`(코인당 잔고)을 넣으면 현실대로 동작합니다.

- 잔고 < 진입금 → 진입 못 함 (놓친 구간 집계)
- 잔고 ≤ 0 → **파산 처리 후 그 시점에 매매 중단**
- `필요잔고` 컬럼: 중간에 안 끊기려면 필요한 최소 계좌 규모 (= 진입금 + 누적손익 최저점)

여러 코인을 동시에 돌리면 코인간 상관이 높아(상위10 기준 ≈0.7) 낙폭이 **코인 1개의 4배 이상**으로
겹칩니다. `필요잔고`를 코인 수만큼 단순 합산하지 말고, 넉넉하게 잡으세요.

# 📈 주식 종가 신호 알림 (`stock_*.py`)

## 먼저: "종가 보면 다음날 오를지 안다"는 사실인가?

**아닙니다.** 종가만으로 다음날 방향을 아는 방법은 없습니다. 알 수 있었다면 이미
모두가 그렇게 하고 있고, 그 순간 그 방법은 사라집니다.

다만 **"동전 던지기보다 아주 조금 나은 확률 편향"** 은 실제로 존재합니다.

| 구분 | 실제 수치 |
|---|---|
| 아무 날이나 다음날 오를 확률 | 약 50~52% (종목·기간에 따라) |
| 잘 먹히는 신호의 적중률 | 53~57% 정도 |
| 즉, 우위(edge) | **+2~5%p** |
| 1일 스윙 왕복 비용(한국) | 약 0.31% (수수료+거래세+슬리피지) |

문제는 이 우위가 **비용보다 작은 경우가 대부분**이라는 겁니다. "적중률 57%"처럼
보이는 신호도 대개 ① 표본이 적어서 우연이거나 ② 특정 기간에만 통했거나
③ 맞아도 수수료·세금 떼면 마이너스입니다.

그래서 이 프로그램은 **예측기가 아니라 검증기**입니다.
"이 신호 진짜 먹히나?"를 숫자로 답하고, **검증을 통과한 신호만** 알림을 보냅니다.
대부분의 종목에서 "통과 신호 없음"이 나오는 게 정상입니다.

## 실행 방법

```bash
python stock_backtest.py             # 검증 리포트 (내 종목, 어떤 신호가 통하나?)
python stock_alert.py                # 오늘 신호 1회 검사
python stock_alert.py --watch        # 매일 장 마감 후 자동 검사 (상주)
python stock_alert.py --all          # 탈락한 신호까지 전부 보기 (참고용)
python stock_alert.py 005930 SPY     # 종목 지정 (한국은 6자리 숫자만)
```

감시 종목·기준·알림 채널은 `stock_config.py`에서 수정합니다.
텔레그램으로 받고 싶으면 `TELEGRAM_TOKEN` / `TELEGRAM_CHAT_ID`만 채우면 됩니다.

## 파일 구조

| 파일 | 역할 |
|------|------|
| `stock_config.py` | 감시 종목, 검증 기준, 비용, 알림 설정 |
| `stock_data.py` | 일봉 수집 (야후 → stooq 폴백 → CSV), 캐시 |
| `stock_signals.py` | 종가 기반 신호 17종 (골든크로스, RSI, 볼린저, 급락 등) |
| `stock_backtest.py` | **핵심**: 신호별 실제 적중률 검증 |
| `stock_alert.py` | 검증 통과 신호만 알림 (콘솔/파일/텔레그램) |

## 검증기가 거르는 4가지 함정

1. **기준 상승확률과 비교** — 적중률 55%는 기준이 52%면 우위가 3%p뿐입니다.
2. **순열검정(1000회)** — 신호 배열을 통째로 밀어 만든 '가짜 신호'와 비교해
   우연히 나올 수 있는 성적인지 판정합니다. 신호가 뭉쳐 나오는 성질과
   주가 자기상관을 보존하므로 단순 z검정보다 정직합니다.
3. **전반기/후반기 + 최근구간(OOS) 분리** — 한쪽 기간에만 통한 신호를 탈락시키고,
   최근 30% 데이터는 검증에 쓰지 않고 '실전 확인용'으로 남깁니다.
4. **비용 차감** — 수수료·거래세·슬리피지를 뺀 뒤에도 플러스인지 봅니다.

신호 17개를 동시에 검사하므로 **본페로니 보정**(α를 17로 나눔)도 적용합니다.
17개를 돌리면 그중 하나쯤은 우연히 좋아 보이기 때문입니다.

### 검증기 자체의 성능 (인공 데이터로 측정)

| 테스트 | 결과 |
|---|---|
| 완전 무작위 데이터 20개 | 헛알람 **1개 (5%)** — 의도한 유의수준과 일치 |
| 일부러 +0.6% 편향 심은 데이터 10개 | **8개(80%) 탐지** |

무작위 데이터에서 적중률 57%짜리 신호가 보여도 전부 탈락시키고,
실제로 편향이 있으면 잡아냅니다.

## 알림 예시

```
🔔 [005930] 2026-09-11 종가 71,200 (-3.00%)
  신호: down3 — 3일 연속 하락 마감 (다음날 상승 기대)
  과거 성적: 적중률 61.7% (아무 날이나 51.1%, 우위 +10.6%p, 206회, p=0.002)
  비용 차감 기대수익: +0.260%/일
  검증 외 최근 구간: 67.6% (74회)
  ※ 이건 예측이 아니라 '과거에 이랬다'는 확률 편향입니다.
```

## ⚠️ 한계 (꼭 읽으세요)

- **과거에 통했다 ≠ 앞으로 통한다.** 시장이 바뀌면 편향도 사라집니다.
  최소 분기에 한 번은 `stock_backtest.py`를 다시 돌려 유효한지 확인하세요.
- **적중률 57%는 43%는 틀린다는 뜻**입니다. 한 번의 신호에 크게 베팅하면
  확률과 무관하게 손실이 납니다.
- 배당·액면분할 미보정 데이터일 수 있고, 거래정지·상하한가 구간은 통계를 왜곡합니다.
- 야후 파이낸스가 막힌 망(회사·일부 통신사)에서는 데이터 수집이 실패합니다.
  그럴 땐 CSV를 직접 받아 `python stock_alert.py 내파일.csv` 로 쓰세요.
- 투자 판단과 책임은 전적으로 사용자 본인에게 있습니다.
