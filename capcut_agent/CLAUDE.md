# CapCut Agent — 작업 메모

## 자막 인식 방식 (고정 — 절대 바꾸지 말 것)

**클립마다 그 클립 소리로만 따로 인식한다.** `transcribe_all_clips`

- 오디오는 `load_audio_16k` 로 **한 번만** 메모리에 올리고, 클립마다 거기서 잘라 쓴다.
  예전 느림의 진짜 원인은 '클립마다 ffmpeg 재실행'이었다. 그걸 없앤 게 속도 핵심.
- 앞뒤 여유 `CLIP_PAD_SEC=0.10초`는 **잘라낸 무음 안에서만** 준다
  (옆 클립 시작/끝을 절대 안 넘음 — 197클립 전수 검증 0건 침범).
- `ASR_WORKERS`개 스레드로 동시 인식 (모델을 `num_workers=ASR_WORKERS`로 열어둠).

### 이어붙여 한 번에 인식하는 방식으로 되돌리지 말 것 (2026-09 실측)

클립들을 이어붙여 몇 번에 나눠 인식하면 5번이면 끝나 빠르지만, **이어붙인 자리에서
다음 클립 첫말이 앞 클립으로 새어 들어간다.** C3995 드래프트 실측:

- 앞 클립 끝말 == 뒤 클립 첫말인 쌍 36/192
- **그중 12건은 두 클립이 원본에서 1.5~10.5초나 떨어져 있어 절대 이어질 수 없는 말**
  (`…풀로 집중해 일단` → `일단 이`, `…팔았거든 근데` → `근데 용인이랑…`)
- 0.23초 클립에 `이 거대한`(4음절) 같은 물리적으로 불가능한 자막도 생김

무음 패딩을 끼우는 것도 금지 — Whisper 가 그 구간을 no_speech 로 보고 통째로 버린다.
whole-audio(전체 인식 후 분배)도 금지 — 경계에서 클립 첫말이 사라진다.

## 크래시 방지 (절대 되돌리지 말 것)

- 모델 로드는 **GPU(float16) 우선 → 실패 시 CPU `compute_type="auto"`**.
- CPU에서 `compute_type="int8"`을 강제하면 그 명령을 지원 안 하는 CPU에서 프로그램이 통째로 꺼진다(Illegal instruction, 파이썬 try/except로 못 잡음).

## 자막 끊기(청킹) 우선순위

- **문장/어미 기준 끊기가 먼저**, 글자 수 제한은 그 다음. (사용자 요청)
- 종결어미(-야/-어/-지/-거야/-잖아 …)로 문장이 끝나고 뒤에 말이 더 있으면
  글자 수와 무관하게 그 자리에서 먼저 끊는다 (`_is_final_ending`).
  단 연결어미(-는지/-면서/-니까 …)와 의존명사(거야/중이야 …)는 문장 끝이 아님 → 제외.
- 문장으로 끝난 조각의 끝말을 다음 조각으로 끌어오지 않는다(`_rebalance_tail` 가드).
- **서술어가 꼬리로 떨어지면 안 된다** — "문장은 이어져야 해" (사용자 요청 2026-09).
  `아쉬워할 필요 / 없어`, `놓을 수 / 있어` 처럼 앞말을 받는 서술어는 붙이거나,
  앞 조각에서 어절을 넘겨 `데이터센터 마당에 / 그냥 놓을 수 있어` 로 고르게 만든다.
  구두점으로 끝난 진짜 독립 문장(`오케이?`)만 꼬리로 남긴다.
- 원인이었던 두 가지 오판을 고쳤다:
  1. `_NOT_FINAL_WORDS` — `필요/캐나다/에너지/올해/분야` 처럼 어미처럼 생긴 **명사**를
     문장 끝으로 보던 것. (`아쉬워할 필요` 뒤에서 끊기던 원인)
  2. `_is_verb_final_eo` — `없어/있어/했어/냈어` 같은 **-어 서술형**을 문장 끝으로
     인식하지 못하던 것. 명사(`단어/영어/용어`)와는 앞 글자 ㅆ받침으로 구분한다.
  3. `_ends_clause` 가 연결어미를 문장 끝으로 보던 것 (C4018 실측).
     `오만해까지` 가 '지'로 끝난다고 문장 끝이 돼서 `오만해까지 / 넓혔어` 로 갈라졌다.
     이제 `_ends_clause = 구두점 or _is_final_ending` (연결어미·의존명사 제외).
  4. `_is_nun_ji` — `뭔지/어떤지` 의 -ㄴ지는 연결어미다 (`헷지가 뭔지 / 알아?` 방지).
  5. `_rebalance_tail` 의 '구두점으로 끝난 꼬리는 그대로' 가드 제거 —
     `되냐?` `알아?` 같은 서술어까지 막고 있었다. 앞 조각이 문장으로 끝났는지로만 판단한다
     (`우리 반이야` + `오케이?` 는 그대로, `반도체는 어떻게` + `되냐?` 는 끌어옴).
- 끊을 자리에 문법 신호가 전혀 없으면(점수 ≤10) **고르게 나뉘는 쪽**을 고른다
  (`_best_break_index`). `반도체 빠지는 날 계좌 / 전체가 빠져` → `… 날 / 계좌 전체가 빠져`.
- `_BINDS_BACK`(같은/처럼/마냥/따위) 앞에서는 끊지 않는다 — `단비 / 같은 수익` 방지.
  ('같이'는 부사로도 써서(`같이 있는 게`) 넣으면 안 된다)
- `_is_obligation` — `-아야/-어야/-해야/-가야`(당위)는 **문장 끝이 아니다**.
  뒤에 `돼/한다`가 온다. (`AI로 막아야 / 돼` 로 갈라지던 원인, C4024 실측)
  단 `소프트웨어야/단어야`는 명사+야라 예외(`_NOUN_EO`).
- `_NO_END_WORDS`(다/이/저/두/첫 …)는 **문장 끝이 될 수 없다** — 뒷말을 꾸미는 말이다.
  부사 `다`가 종결어미 '-다'로 오인돼 `두 줄 다 / 잡고 있어` 로 갈라졌다.
- 한 숫자를 쪼개지 않는다 — 앞말이 `만/천/억/조`로 끝나고 뒷말이 숫자로 시작하면 점수 0.
  (`사상 최고가 10만 / 9천을 찍었어` 방지)
- ㄹ관형형 + 맨명사는 붙여 둔다 (`_ends_rieul`) — `수혜 받을 / 기업` 방지.
  목적격 `-를`은 제외하고, 뒷말이 조사·어미를 달고 있으면 적용 안 함.
- **글자 수는 '12자 내외'지 딱 맞춰야 하는 값이 아니다** (사용자 요청:
  "무조건 맞추게 하지마, 12자 내외인 거지"). `_absorb_tiny_groups` 로
  2~3글자 조각은 옆 조각에 붙인다 (`hard+3`까지 허용).
  단 구두점으로 끝난 진짜 한 문장(`놉.`, `오케이?`)은 그대로 둔다.
  ※ 상한 자체를 늘리는 방식(stretch)은 검증된 규칙 4개를 깨뜨려서 쓰지 않는다.

## 같은 말 반복 → 영상 클립 자르기 (C4023 요청)

사용자 요청: "같은 단어 2개 나오면 영상이랑 자막클립 잘라줘".

`split_clips_at_repeats(keep_ranges, segments)` — 자막 인식이 끝난 뒤
(`ng_short` 처리 다음) 호출한다. 한 클립 안에서

1. **두 어절 이상이 통째로 다시 나오면** (테이크 재촬영)
   `잠깐 MLCC 세계 1위 무라타가 | 잠깐 MLCC 세계 1위 무라타가`
2. **같은 말이 바로 뒤/두세 어절 안에 다시 나오면**
   `받아 | 받아`, `올해 예상은 | 올해 이상은`

그 자리에서 **영상 클립(keep_ranges)을 자른다**. 자막은 따로 손댈 필요 없다 —
단어가 원본 시각을 들고 있어 `map_words_to_timeline` 이 새 클립으로 다시 배정한다.

- **띄어쓰기가 달라도 같은 말로 본다** — 어절 단위가 아니라 글자를 이어붙여 비교한다.
  `같은 판에서` 와 `같은판에서` 는 붙이면 둘 다 `같은판에서` (C4023 실측 누락 원인).
- 3글자 미만 반복, 8어절 넘게 떨어진 반복은 제외. 조각은 최소 0.30초.
- 반복 구간 안에서 또 자르지 않게 찾은 지점으로 건너뛴다.

## 클립 끝 잡음 떼기 (C4023 요청)

사용자 요청: "뒤에 간혹가다 말하는 내용이 아닌 것들이 자꾸 붙어, 2·3글자들이".

`trim_trailing_noise(words, script_tokens)` — `refine()` 안에서 호출.

- `_TRAILING_NOISE`(아우/으/삐/골/흠 …)에 있으면 계속 떼어낸다.
- **대본이 있으면** 대본에 없는 3글자 이하 꼬리를 한 번 더 뗀다 (가장 정확한 방법).
- `자/네/놉/빵` 처럼 실제로 쓰는 말은 목록에 **넣지 말 것**.
- 최소 한 단어는 남긴다.

## 자막 나누기 기준 (손편집본 5ec41315 기준)

사용자가 직접 편집한 드래프트를 정답으로 삼는다. 그 파일의 실제 수치:

- 말 있는 영상 클립 47개 → 자막 105개 = **클립당 평균 2.2개** (1~4개)
- 자막 글자 수: 중앙 9자 / 상위10% 12자 / 최대 16자, **전부 한 줄**
- 자막 한 조각 길이 0.27~1.83초, 클립 안에서 빈틈없이 이어짐
- 예) `첫째` / `수주가 끊겼어?` / `놉!`  — 1.53초 클립에 자막 3개

따라서:

- 자막은 **언제나 한 줄** (줄바꿈 금지). 대신 클립 안에서 **문장 단위로 여러 조각**으로 끊는다.
  ("영상 클립 하나당 자막 하나"는 클립 경계를 넘지 말라는 뜻이지 개수 1개가 아니다 — 오해했던 부분)
- 자막은 영상 클립 경계를 넘지 않는다. 클립의 자막들이 클립 시작~끝을 빈틈없이 채운다.
- 자막 시작은 클립 시작. 단 0.4초(`LEAD_SNAP_US`) 넘게 늦게 말하면 그 시각부터.
- **조각이 글자 수에 비해 너무 짧게 스쳐 지나가지 않게 시간을 다시 나눈다**
  (`fit_chunk_durations`, 상한 `READ_CHARS_PER_SEC=11.0` — 손편집본 실측 최대 11.1자/초).
  Whisper 단어 시각은 클립 앞쪽에서 자주 뭉쳐서, 4.63초 클립인데 '놓친 사람 스톱!'(7자)이
  0.30초(23자/초)만 뜨는 일이 생겼다(C4001 실측). 부족한 조각을 먼저 채우고 남는 시간은
  원래 여유가 있던 조각에 비례 배분 → 말한 순서·시각은 지키면서 깜빡 자막만 없앤다.
  클립 시작~끝을 빈틈없이 채우는 불변식은 유지(81클립 검증, 어긋남 0).
- 숏츠 `sub_chars` 기본 10 (손편집본 중앙 9자에 맞춤).
- 관형형(`_is_adnominal_word`: 가는/없는/싶은/물린 …) 뒤에서는 끊지 않는다 —
  손편집본이 이 자리를 한 번도 끊지 않았다. 단 조사 '-는'(에서는/까지는)은 끊어도 된다.
- **같은 말을 여러 번 해도 전부 그대로 남긴다.** 사용자 요청:
  "앞에 자막이 나왔다고 뒤에 안 나오는 게 아니라 다시 나와야 해" (2026-09).
  이전에 넣었던 중복 제거(`dedupe_clip_words`)는 이 요청으로 **삭제**했다.
  (그 전 요청이었던 "중복 단어 있으면 하나만"은 철회된 것으로 본다 — 다시 넣지 말 것)

## 대본 반영 (사용자 요청: "대본 참고해서 자막 클립이 생성되야하고")

`align_clip_to_script` — 클립마다 대본의 해당 구간을 찾아 **대본 문장 그대로** 자막을 만든다.

- 철자/띄어쓰기 교정은 물론, **인식이 놓친 단어를 대본대로 채워 넣는다**
  (예전엔 대본에만 있는 단어는 안 넣었음 → 이제 넣음).
- 엔지컷 보호 장치 2개 — 조금만 말하고 끊긴 클립을 부풀리지 않기 위해:
  1. 대본 한 문장의 65%(`SENT_COVER`) 이상을 말한 클립만 그 문장 전체로 확장.
  2. 클립 끝에 **말할 시간이 남아 있을 때만** 뒷말을 채운다
     (`tail_room_us`, 한 글자 0.13초로 환산, 같은 문장 안에서 최대 4단어).
     말 끝나자마자 잘린 NG 컷은 남는 시간이 없어 그대로 둔다.
- 대본에 없는 애드립은 인식 원문 그대로 유지.
- 대본은 줄바꿈도 문장 경계로 본다(`build_script_index`).

## 자막 후처리 정책

- 자막 후처리(중복 합치기·끝음절 흡수 등)는 **넣지 않는다** — 사용자가 원치 않음. `subtitle_chunks_for_timeline`은 인식 결과를 그대로 반환.
- 숫자/영어 잡음 필터(`clean_recognized_text`, `_is_number_babble`, `is_hallucinated_line` 등)는 유지 — `I`, `it`, `2 2 3` 같은 헛것 제거에 필요.

## 테스트

- `python3 tests/자막_기준_테스트.py` — 자막 끊기 gold 테스트. 변경 후 반드시 통과 확인.
- 이 환경(샌드박스)엔 Whisper 모델·GPU 가 없어 실제 인식은 못 돌린다. 순수 파이썬 로직(분배·필터·청킹)만 여기서 검증 가능.
- 단, **ffmpeg 은 `pip install imageio-ffmpeg` 로 쓸 수 있다**
  (`imageio_ffmpeg.get_ffmpeg_exe()`). 무음 감지(silencedetect)·오디오 레벨 분석은
  업로드된 원본 오디오로 실제 검증 가능하다.
